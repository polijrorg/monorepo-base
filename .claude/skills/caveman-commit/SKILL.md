# Caveman Commit

Generate commit message. No fluff.

## Format

```
<type>(<scope>): <summary>
```

- Subject ≤72 chars, ideally ≤50
- Imperative verb: "add", "fix", "remove", "update"
- No terminal punctuation
- No emoji unless project uses them

## Valid types

`feat` `fix` `refactor` `perf` `docs` `test` `chore` `build` `ci` `style` `revert`

## Body — only when needed

Include body only for:
- Non-obvious reasoning
- Breaking changes
- Migration steps
- Issue references (`Closes #42`)

Omit body when subject says enough.

## Never include

- "This commit does..."
- First-person pronouns
- "Generated by Claude" or any AI attribution
- Redundant file paths already implied by the type/scope

## Process

1. Read `git diff --cached` (staged changes)
2. If nothing staged, read `git diff HEAD`
3. Identify the dominant change — one commit, one concern
4. Output the message text only — do not run git commands
